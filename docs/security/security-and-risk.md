# 安全、隐私与风控

## 1. 范围与原则

AIToHuman 涉及现实世界行动、位置、身份、聊天、图片以及未来资金交易，风险高于普通内容应用。设计遵循最小权限、最少披露、默认拒绝、可追溯和人工可介入原则。

本文是工程基线，不替代首发地区的专业法律意见。

## 2. 任务风险分类

### 允许自动发布

低风险、合法、无需资质、可明确验收的普通取送、排队、公开场所拍照和信息核验。

### 需要人工审核

- 描述含糊但可能涉及敏感物品或私密场所。
- 高金额、深夜、偏远地点或异常频率任务。
- 需要处理个人证件副本或访问受限区域。
- AI 和规则的判断不一致或置信度不足。

### 禁止发布

- 违法、暴力、欺诈、骚扰、跟踪、偷拍或侵犯隐私。
- 枪支、毒品、危险品、违禁品或受监管物品交易。
- 代考、冒名、代签、破解账户或规避官方身份验证。
- 医疗诊断/治疗、金融账户操作和其他必须由持证人员执行的高风险事项。
- 可能危害服务者、用户或第三人的行为。

规则使用稳定的原因代码和版本，不只依赖模型自由文本。

## 3. AI 风险边界

- 用户输入、外部网页、附件和模型输出全部视为不可信。
- 系统提示与业务规则不依赖前端保密。
- 模型不能直接发布任务、改变订单、访问任意文件或执行付款。
- 结构化输出通过 JSON Schema、长度、枚举、金额和日期校验。
- 确定性规则优先于模型允许结果；敏感决策可进入人工队列。
- 对提示注入、越权工具调用、信息泄露和规则绕过建立回归测试集。

## 4. 隐私分级

### 公开层

大厅可显示标题、类别、粗略区域、时间窗口、固定悬赏和脱敏描述。AI 建议区间不作为服务者可议价的交易条件展示。

### 订单参与者层

订单成立并达到规定状态后，披露执行需要的精确地点、联系方式代理和私密说明。

### 高敏层

身份证件、认证材料、支付标识和争议证据只对专用服务及授权运营角色开放，并记录访问审计。

收集每个字段前应说明用途、保存期限和删除策略。开发、测试和分析环境使用合成或脱敏数据。

## 5. 应用安全基线

- 密码采用成熟的 Identity 哈希策略，不自行实现密码学。
- Refresh Token 哈希保存、轮换并检测重复使用。
- 管理员启用多因素认证和独立授权策略。
- API、登录、AI 和文件授权均实施速率限制。
- 防范常见 Web 风险：XSS、CSRF、SQL 注入、SSRF、开放重定向和不安全反序列化。
- CORS 只允许明确来源，不在带凭证请求中使用通配符。
- 密钥存入秘密管理系统，不提交仓库或写入日志。
- 运营可配置的机密（模型 API Key、对象存储与扫描服务密钥）用 Data Protection 加密后存进 `system_settings`，接口与审计只返回掩码与指纹；加密密钥环由部署环境提供（`DataProtection__KeysPath`），不入库也不进仓库，多实例必须共享同一密钥环。
- 配置表只接受设置目录（白名单）里的键，连接串、日志级别、密钥环路径这类部署级配置不能通过运营接口修改；管理员名单（`Admin__UserIds` / `Admin__Emails`）同样只由部署控制，避免“改配置即提权”。
- 每次配置变更在同一事务内写审计（键、动作、脱敏前后的值、操作人、时间），审计只追加；同一时刻的多条记录之间不保证先后顺序。
- 依赖自动扫描，建立安全补丁响应流程。

## 6. 文件与图片

- 对象存储 Bucket 默认私有。
- 上传限制类型、大小、数量和速率。
- 扫描恶意文件，图片重新编码并按需要去除 EXIF 定位。
- 文件名由系统生成，原始文件名仅作为显示元数据并清洗。
- 下载前重新检查当前用户与订单关系，签名 URL 短时有效。
- 对争议保全与用户删除请求建立明确的保留优先级。

## 7. 现实安全

- 服务者准入等级与可接任务风险相匹配。
- 精确地址延迟披露，双方联系方式优先使用代理渠道。
- 提供举报、退出、异常上报和紧急求助入口。
- 避免鼓励驾驶中操作、违规排队、进入危险或未授权区域。
- 高风险时段和地点可限制发布或要求额外验证。

## 8. 支付与欺诈

正式支付上线前必须完成支付服务商、托管/分账资质、退款规则和账务设计评审。不得把普通数据库余额当作真实钱包上线。

支付接入后至少需要：

- 回调签名验证、重放防护和幂等处理。
- 内部不可变账本及每日对账。
- 异常悬赏、私下加价诱导、关联账户、刷单、拒付和提现风控。
- 争议期间冻结结算，不直接删除交易记录。

## 9. 审计与事件响应

关键事件包括登录异常、身份和角色变化、任务风险决策、精确位置访问、悬赏变化、报名选择、订单状态、评价公开/隐藏、凭证访问和管理员操作。

应预先定义：

- 安全事件负责人和联系渠道。
- 事件分级、隔离、证据保存和通知流程。
- 密钥泄露、账户接管、隐私泄露和恶意任务的处置手册。
- 日志、对话、位置、凭证和审计记录的不同保留期限。

## 10. 上线前检查

- 完成威胁建模和越权测试。
- 验证禁止任务测试集和人工审核路径。
- 验证对象存储无匿名读取权限。
- 验证日志、错误响应和监控不包含敏感内容。
- 验证备份加密及恢复演练。
- 完成隐私政策、服务条款、服务者协议和地区合规评估。
