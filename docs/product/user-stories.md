# 用户故事与验收标准

## 1. 用户与 AI

### US-001：通过对话描述需求

作为用户，我希望用自然语言描述目标，以便不填写复杂表单也能开始创建任务。

验收标准：

- 系统展示用户消息和 AI 回复。
- 会话可继续，刷新页面后历史仍存在。
- AI 请求失败时保留用户输入并允许重试。

### US-002：补充缺失信息

作为用户，我希望 AI 只询问完成任务所需的关键信息，以便快速得到可靠草稿。

验收标准：

- 缺少地点、时间、预算或验收条件时，系统标记对应字段。
- 关键字段未满足前不能发布。
- 用户可直接编辑 AI 推断错误的字段。

### US-003：确认任务草稿

作为用户，我希望发布前看到完整任务，以便确认公开内容和私密内容。

验收标准：

- 预览区分别展示大厅公开信息和接单后披露信息。
- 用户必须主动点击确认发布。
- 任何编辑都会使之前的确认失效并触发重新校验。

## 2. 任务大厅与报价

### US-101：浏览适合的任务

作为服务者，我希望按区域、分类、截止时间和预算筛选任务，以便找到可以完成的工作。

验收标准：

- 仅展示处于可报价状态且未过期的任务。
- 未授权用户看不到精确地址和联系方式。
- 列表支持分页并保持筛选条件。

### US-102：提交报价

作为服务者，我希望提交价格、预计到达时间和说明，以便用户判断是否选择我。

验收标准：

- 服务者必须满足账户状态、类别和区域要求。
- 报价必须为正数且符合平台配置范围。
- 同一服务者的有效报价不可重复，可在截止前按规则更新或撤回。

### US-103：选择服务者

作为用户，我希望比较报价和服务者信息并选择一人，以便形成订单。

验收标准：

- 只有任务所有者能选择报价。
- 并发选择两份报价时最多成功一份。
- 订单保存选中报价、任务说明和验收条件的不可变快照。

## 3. 执行与验收

### US-201：更新执行进度

作为服务者，我希望按实际情况更新订单状态，以便用户了解进度。

验收标准：

- 只允许状态机定义的下一步。
- 每次变更记录操作者、时间和备注。
- 用户收到任务状态变化通知。

### US-202：提交执行凭证

作为服务者，我希望上传约定的凭证，以便证明任务已完成。

验收标准：

- 仅允许配置的类型、大小和数量。
- 文件上传成功不等于验收提交成功。
- 凭证只能由订单参与者和授权管理员访问。

### US-203：验收或拒绝

作为用户，我希望按约定标准验收结果，以便确认完成或要求补充。

验收标准：

- 用户可查看任务快照及全部凭证。
- 拒绝必须选择或填写具体原因。
- 已完成订单不能通过普通接口退回执行中。

## 4. 安全与运营

### US-301：拦截禁止任务

作为平台，我希望在发布前拦截违法、危险或侵犯隐私的任务，以降低伤害和合规风险。

验收标准：

- 禁止类别不会被发布。
- 决策保留规则版本、原因代码和审计记录。
- 不向普通用户泄露可用于绕过规则的详细检测逻辑。

### US-302：处理争议

作为运营人员，我希望查看完整订单证据并记录裁决，以便一致地处理争议。

验收标准：

- 可查看任务与报价快照、状态事件、双方消息和凭证。
- 裁决必须填写依据，所有操作进入审计日志。
- 普通管理员权限不足时不能执行退款或账户永久封禁。
