# ADR-0003：三方集成参数改为运营可配置（配置表 + 加密机密）

- 状态：已接受
- 日期：2026-09-12
- 相关：[系统架构](../system-architecture.md)、[安全、隐私与风控](../../security/security-and-risk.md)、[交接文档](../../development/handoff.md)

## 背景

首批接入的三方能力（模型服务、对象存储、内容/病毒扫描）此前只能写死在配置文件或环境变量里：

- 换一个模型、换一个扫描服务商、把凭证从本机目录搬到对象存储，都需要改配置并重启进程；
- 密钥只能放在部署环境里，运营人员没有自助修改的入口；
- “哪个键生效过、谁在什么时候改的”没有记录，出问题只能翻部署历史。

同时已经明确：数据库连接串、Redis、日志这类**部署级**配置不能交给运营后台，否则一次误改会让实例起不来。

## 决策

1. **设置目录（白名单）**：只有登记在 `SettingCatalog` 里的键才能通过后台读写。每个键声明类型（String/Bool/Int/Url/Choice）、是否机密、默认值，以及兼容的环境变量名。未注册的键一律 `400`。
2. **解析顺序固定**：数据库覆盖 → 环境变量/配置文件 → 代码默认值。删除覆盖记录即恢复默认，不需要额外的“启用/停用”状态列。
3. **机密加密落库**：`ai.apiKey`、`storage.s3.secretAccessKey`、`evidence.scanner.apiKey` 等用 ASP.NET Core Data Protection 加密后写入 `system_settings`，密文带 `dp1:` 前缀；接口与审计只返回掩码与指纹，明文只在服务端内存中出现。密钥环来自部署环境（`DataProtection__KeysPath`），不存放在配置表里。
4. **写入即可生效**：写入成功后刷新进程内的配置快照，消费方每次调用都重新读，因此不需要重启；另有 15 秒一次的后台轮询，用于同步“绕过 API 直接改库”或其他实例的修改。
5. **审计与并发**：每次写入都在同一事务里追加一条 `system_setting_audits`（键、动作、脱敏前后的值、操作人、时间）；覆盖行带 `Version` 乐观并发令牌，客户端可用 `expectedVersion` 提交，冲突返回 `409`。
6. **运营身份来自部署配置**：管理员名单是 `Admin__UserIds` / `Admin__Emails`，刻意不放进可后台修改的配置表，避免任何能改配置的人把自己提成管理员。没有配置管理员时，运营接口对所有人返回 `403`。
7. **不静默降级**：配置成 `storage.provider=s3` 而代码里还没有对应实现时直接报错，不退回本机目录；扫描不可用时按失败模式返回“待扫描、不可下载”，而不是放行或丢弃用户文件。

## 被拒绝的方案

- **全部塞进 `appsettings`/环境变量**：运营无法自助调整，每次都要发版或改部署。
- **通用键值表（任意键都能改）**：等价于把整个 `IConfiguration` 暴露给后台，连接串、日志级别、密钥环路径都能被改写，风险不可控。
- **机密也存明文/只做 Base64**：数据库快照、备份、日志都会泄露密钥。
- **把管理员名单也做成可配置项**：权限自举，任何能改配置的人都能提权。

## 后果

- 新增一张 `system_settings`（覆盖值 + 并发令牌）与一张 `system_setting_audits`（只追加）。
- 消费方（AI、存储、扫描）从“构造时读一次”改成“每次调用读快照”，因此改配置立即生效；代价是每次调用多一次字典查找。
- 机密进数据库扩大了攻击面，必须配套：加密密钥环不入库、接口脱敏、审计留痕、管理员名单由部署控制。
- 本仓库目前只提供后端 API；运营后台页面与“凭证重扫”“对象存储实现”等仍待补，见 [交接文档](../../development/handoff.md) 第 12 节。
