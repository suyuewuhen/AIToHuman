# ADR-0001：采用前后端分离的模块化单体

- 状态：Accepted
- 日期：2026-09-09

## 背景

项目需要快速验证 AI 建单与真人履约闭环，同时任务、报价、订单、验收和未来支付之间存在较强的一致性要求。团队希望后端使用 C#，前端使用 Vue。

## 决策

- 前端采用 Vue 3 + TypeScript，通过 REST API 和 SignalR 访问后端。
- 后端采用 ASP.NET Core 模块化单体。
- 业务模块有明确代码和数据所有权，但初期部署为一个主要应用。
- 核心数据使用 PostgreSQL；Redis、对象存储和 Hangfire 提供辅助能力。
- 模块间不通过共享实体任意修改数据，而通过应用用例和领域事件协作。

## 理由

- 单次请求可用数据库事务维护关键不变量。
- 本地开发、测试、部署和排错成本低于微服务。
- C# 类型系统适合实现明确状态机和业务规则。
- 清晰模块边界为未来按实际负载拆分保留路径。

## 后果

正面影响：交付速度较快、事务简单、可进行端到端重构和测试。

需要承担：必须通过架构测试和代码评审防止模块边界退化；单体部署故障域较大；某些模块不能独立扩缩容。

## 重新评估条件

出现以下证据时重新评估拆分：

- 消息或文件处理负载显著影响核心交易 API。
- AI 调用需要独立的容量、发布节奏或安全边界。
- 团队规模导致单一发布单元成为持续瓶颈。
- 法规要求特定数据或处理过程物理隔离。
