# ADR-0002：固定悬赏、报名制与双向评价选择

- 状态：Accepted
- 日期：2026-09-09

## 背景

允许服务者互相竞价或与用户议价，可能带来误导性低价、选中后加价和反复扯皮。与此同时，现实任务不应只由用户单向选择；服务者也需要根据用户历史信用决定是否报名。

## 决策

- AI 根据任务属性和可用历史数据向用户提供建议金额或区间，并说明主要估价因素和不确定性。
- AI 建议价本身不修改草稿；只有用户填写并确认的金额才成为任务悬赏。
- 最终悬赏由用户确认，AI 无权替用户定价或加价。
- 服务者只能按任务显示的固定悬赏报名，不能提交价格或附加私下加价条件。
- 用户在任务分配前可以提高悬赏；发布后不能降低悬赏，降低价格需取消并重新创建任务。
- 服务者报名前可查看用户公开评价，用户选择前可查看服务者公开评价。
- 完成订单后双方独立评价。双方均提交或订单完成满 7×24 小时后才公开，降低报复性评价；期限使用 UTC 计算并作为可调整的平台配置。
- 用户评价与服务者评价按被评价角色分别汇总，不混为单一信用分。

## 理由

- 固定悬赏使任务大厅的价格真实、可比较，减少议价成本和阴阳报价。
- 用户加价提供市场反馈出口，又不会损害已报名服务者利益。
- 双向可见的真实履约评价让双方都有选择权。
- 评价盲期降低一方根据对方评分进行报复的动机。

## 后果

正面影响：交易条件简单，订单快照和支付金额更清晰；匹配过程更易审计；用户与服务者都能管理交易风险。

需要承担：AI 建议价冷启动可能不准；低价任务可能长期无人报名；平台需要识别消息中的私下加价诱导；评价系统需要申诉、内容审核和反刷机制。

## 后续决策

- 建议价的冷启动规则、数据特征和更新频率。
- 默认评分维度、公开展示和申诉时限；根据试点数据评估是否调整 7 天评价期。
- 连续加价的频率限制与通知策略。
